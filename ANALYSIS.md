# Static investigation

Target: `TWFC.exe` open in Ghidra, preferred image base `0x10900000`. The installed file's bytes were compared with Ghidra at the patch sites and streaming entry. The game uses compiled UnrealScript wrappers whose pointers often refer to UObject + 0x10. Most symbols are autogenerated. Function roles below are inferences from control flow and callers, not recovered original names.

## 1. Locally controlled pawn character-load path

Function at `0x10BA0990` calls the controller/local-control predicate at `0x11437D60`. When it succeeds, it clears previous residency assignments through `0x10BEC020`, then calls the material/texture residency helper at `0x10BEC120` with `true` for the current character and an additional character asset. The two calls are at `0x10BA09C7` and `0x10BA09E3`. The same function later checks the controller against `TnPlayerController`.

The predicate at `0x11437D60` checks that the pawn has a controller at +0x1D4; in networked worlds it calls controller virtual methods at +0x140 and +0x354. This supports a locally controlled pawn interpretation. Live verification was unavailable.

Relevant simplified behavior:

```text
if (controller/local-control predicate(pawn)) {
    clear previous character residency;
    set character textures resident(true);
    set additional character textures resident(true);
}
```

## 2. Character material residency helper imposes reduction of 1

At `0x10BEC120`, the code iterates materials and their textures, checks each texture against `Texture2D`, and sets/clears fields:

```text
if (enable) {
    texture.flags_at_7c |= 4;
    texture.reduction_at_80 = 1;
} else {
    texture.flags_at_7c &= ~4;
    texture.reduction_at_80 = 0;
}
```

The important instructions are `OR [ESI+0x6C],4` at `0x10BEC1B7` and `MOV [ESI+0x70],EBP` at `0x10BEC1BB`. In this function EBX is initialized to zero at `0x10BEC12A`, and EBP to one at `0x10BEC153`. ESI = texture object + 0x10. Consequently, replacing the MOV's ModRM byte from 0x6E to 0x5E writes EBX (zero) while leaving the flag and loop-counter register intact.

A separate single-texture helper at `0x10BEC220` performs the same assignments, including `MOV [EAX+0x70],1` at `0x10BEC22B`. It is patched too for consistency, although no direct callers of that helper were established in this investigation. This additional patch does not broaden the patch to the engine's general forced-residency implementation.

The shared material helper is also used by the character swap/preview path at `0x10BEA570`, which references `TnAiPawn`. Therefore these setters are not guaranteed to operate exclusively on a player object.

## 3. Streaming consumer subtracts that exact field

At `0x11541540`, the mip selection routine routes forced-residency textures (flags & 0x2C) to `0x1154202F`. It also uses this branch when its streaming flag is disabled or its resource has the sentinel priority, so the branch is not exclusively a player branch.

At `0x1154202F`:

```text
eax = texture.total_mips_at_68;
eax -= texture.reduction_at_80;
wanted_mips = max(eax, 0);
priority = INT_MAX;
result = clamp_wanted_mips(wanted_mips);
```

The subtraction is `SUB EAX,[ECX+0x80]` at `0x11542032`. The clamp at `0x115307D0` still considers available mips, a cached LOD reduction and minimum residency. With the character helper's value of one, a texture with N mips requests N−1 in this branch. With zero it requests N before the normal clamps.

An additional unused-looking helper at `0x10EB4190` contains the same `max(total−reduction,0)` arithmetic. It was not patched. Changing the assignments corrects the field for every consumer and avoids altering unrelated forced-residency behavior.

## Candidate fix

Patch the two game-specific setters to write zero. Keep forced residency enabled and leave the streaming routine and texture group limits unchanged. Inject before the character textures are initialized, or refresh the character afterward.

This directly explains how locally controlled character loading can lose exactly one mip while ordinary distance-based NPC streaming does not. It is a strong static candidate; actual runtime field values and visual results have not been measured. Asset cooking limits, cached LOD clamps, another later field assignment, or shader sampling could still prevent the expected visual result.

## Verification

- Built DLL and test executable using MSVC 14.51.36231 targeting x86, C++17, `/W4 /WX`, static release runtime.
- Ghidra and local-file patch instruction bytes agree.
- The DLL applies only two byte replacements and uses build/signature checks, page protection changes and instruction-cache flushing.
- Synthetic-image tests included for protection, relocation, restoration and rejection cases. Windows denied launching the compiled test executable in this session; these runtime tests are **not verified**.
- No game process was injected or launched for testing. No debugger server was running at the bridge's expected endpoint.
- Ghidra function definitions were created at `0x10D78F10` and `0x10BA0990` to inspect previously undefined code. No binary bytes were changed in Ghidra or on disk.
